# fajita: Adreno 630 GPU bring-up (SDM845, a6xx gen1)

Goal: hardware-accelerated rendering for iOS 16.7.16 on the OnePlus 6T, so SpringBoard/CARenderServer composites through
the Adreno 630 instead of the CPU. The iPadOS 17 stack (sheng, Adreno 740) is the template; this note records the A630 and
iOS 16 port. Branch `gpu-port` of the board repo; the kernel/driver changes are in the UniXNU-fajita fork's own copies.

## Shape of the port

Reused from the sheng stack, unchanged except as noted:
- `drivers/NativeAdreno` (fork copy): the GMU and GPU SMMU contexts, BO memory, VM, ring, submit, user client. Three small
  changes: the GMU and GPU context payload sizes and buffer layout are board-settable (`NativeAdrenoGmuContextSetSizes`,
  `NativeAdrenoGpuContextSetLayout`), the GPU context takes a single stream (slot1 == ~0u), and the ring has an A6XX framing
  mode (`setA6xx`).
- `kits/ArmSmmu4K` (native 4 KiB stage-1 tables, context and stream programming), `kits/AdrenoPM4` (TYPE4/TYPE7 helpers).
- NativeMetal, metal2vulkan, Turnip: userland, rebuilt for arm64 iOS 16 and the A630 on CI (not yet wired here).

New, in this repo:
- `drivers/FajitaAdreno/` — the A630's own power-up and legacy GMU, a line-by-line port of the Linux v6.16 msm paths an A630
  takes (clocks, PDC/RSC, HFI v1, hw_init, CP). `A630Regs.h` is generated by `scripts/derive-a630-hwinit.py` from the msm
  register XMLs and `a6xx_catalog.c`. Host tests in `tests/test_a630.c` run every sequence against a register model and a
  simulated GMU firmware.
- `package/FajitaGpuProbe.cpp` — the staged bring-up, run from the boot-progress monitor (`fajita-gpu=<n>`) or the USB debug
  command `gpu <n>`.
- `scripts/build-fajita-gpu.py` — `libFajitaGpu.a` (the probe, the A630 code, the NativeAdreno GMU/GPU/SMMU/ring objects and
  the sha256-pinned firmware), force-loaded by `ios16/configs/fajita_ios16_gpu_defconfig`.

## A630 vs A740, the parts that differ (all handled in drivers/FajitaAdreno)

| Item | A740 (sheng) | A630 (fajita) |
| --- | --- | --- |
| GMU | modern HFI, block-format image, PDC in AOP | **legacy**: HFI v1, flat 32 KiB ITCM image, SPTPRAC, GX rail OOB, kernel programs the PDC sequencer (offset 0x30080) |
| Bus interface | GBIF | **VBIF** (`VBIF_GATE_OFF_WRREQ_EN = 9`, no GBIF halt) |
| APRIV / power-up list | yes | **none**: `CP_RB_CNTL` needs NO_UPDATE and the RPTR comes from `CP_WHERE_AM_I` |
| CP init / submit | `a7xx_cp_init`, BR/BV `CP_THREAD_CONTROL`, `CACHE_FLUSH7` | `a6xx_cp_init` (`CP_ME_INIT` 8 dwords), `CP_EVENT_WRITE CACHE_FLUSH_TS`, CCU invalidates |
| hwcg / protect | a740 tables | `a630_hwcg`, `a630_protect`, `RBBM_CLOCK_CNTL 0x8aa8aa02`, gmu_cgc 0x00020202 |
| GMEM / VA | 3 MiB, no quirk | 1 MiB, 4 GiB VA limit (buffers below 4 GiB) |
| Firmware | a740_sqe.fw, gmu_gen70200.bin | a630_sqe.fw (v0x207, has WHERE_AM_I), a630_gmu.bin, OnePlus a630_zap.mbn |
| Chip id | 0x43050a01 | 0x06030002 (GMU chip id massaged to 0x06030100) |

## Stages (`fajita-gpu=<n>`, or the USB command `gpu <n>`)

1. read-only snapshot (GCC, GPUCC, SMMU IDs, GMU state)
2. `A630PowerCx`: GCC GPU clocks, gpu_cx_gdsc, gpu_cc_cxo
3. `A630GmuClocks`: gpu_cc_gmu_clk_src at 200 MHz, gpu_cc_cx_gmu_clk
4. the GMU's SMMU context (bank 1, SID 5) and the command-DB ARC votes
5. `A630RpmhInit` + `A630GmuColdStart`: PDC/RSC, ITCM load, CM3 release, GX rail vote, SPTPRAC, HFI v1
6. OOB GPU_SET, GX on
7. the GPU's SMMU context (bank 0, SID 0), the SQE, `A630HwInit`, ring, `CP_ME_INIT`, a `CP_MEM_WRITE` fence
8. zap shader (a630_zap.mbn via SCM PAS 13 into gpu_mem 0x8c415000) and `CP_SET_SECURE_MODE 0`
9. the GPU interrupt (SPI 300 = INTID 332) and a fenced `CP_MEMCPY`

Each stage runs only after the earlier ones pass; a failure stops and is reported. `gpu log` dumps the log, `gpu regs` a
register snapshot, `gpu retry` clears a failure. Every run has the sheng-autoreset + wdstop + APSS-watchdog backstop.

## Facts learned on hardware (USB peek/poke and the staged runs)

- UEFI leaves `gcc_gpu_cfg_ahb_clk` on (it is CLK_IS_CRITICAL) and the GPUCC/GX GDSCs collapsed.
- `gpu_cx_gdsc` must be powered **before** the voted GCC branches: `gcc_gpu_memnoc_gfx_clk` reads CLK_OFF until the CX
  domain is up (it is in the GPU_CX power domain). The GDSC enable now precedes the memnoc/axi branch waits.
- The adreno SMMU (0x5040000) stream registers have the Qualcomm firmware quirk: a **FAULT-type S2CR write is ignored**, and
  a **BYPASS write lands as FAULT** (confirmed live: bypass 0x00010000 read back 0x00020000). Reset S2CRs read 0x000200ff
  (FAULT, CBNDX 0xff), which `ArmSmmu4KAttachStreams` rejects as not-clean-FAULT. The probe normalizes the GMU/GPU slots by
  writing BYPASS with CBNDX 0, which the firmware stores as the clean FAULT the kit leases. SMR and translation-type S2CR
  writes stick; context-bank registers (CBAR, TTBR0, ...) are writable. This is the same quirk arm-smmu-qcom handles in
  `qcom_smmu_cfg_probe`.

## Status

Reached GMU clocks (stage 3) on hardware; stage 4 (SMMU context) was blocked by the S2CR quirk, now fixed, under test. The
USB debug channel carries a kernel MMIO/memory peek (`drivers/NativeDwc3/UsbDbgKernelTarget.h`, `read32`/`write32`/`kcmd`),
so GPU/GMU registers can be poked live without a rebuild — the bring-up above was debugged that way.

## Build and run

```sh
# kernel + payload (the build script fetches and merges origin/ios16-port first)
bash scratchpad/build-kernel16-gpu.sh
bash scratchpad/build-payload16-gpu.sh usb-debug=3 fajita-gpu=1 sheng-autoreset=300
scratchpad/cycle.sh gpuN scratchpad/payload16-gpu.img scratchpad/boot-kc.img   # USB log streams by default
# drive the stages over the hub:
scripts/fajita-usbdbg-hub.py call kcmd gpu 5     # run stages 2..5
scripts/fajita-usbdbg-hub.py call kcmd gpu log   # the staged log
scripts/fajita-usbdbg-hub.py call kcmd gpu regs  # a register snapshot
```

Host tests (no phone): `cc -std=c11 -I drivers/FajitaAdreno drivers/FajitaAdreno/tests/test_a630.c
drivers/FajitaAdreno/A630Gmu.c drivers/FajitaAdreno/A630Gpu.c && ./a.out`.
